**MED**
1. `src/pages/api/admin/[...path].ts:61-69` (`publicPaths`) + `:72-75` (`purge`). Publishing, editing or scheduling a post never purges the game hub. A post with `sites: ["games"]` (or a game_slug) is listed by `/` and `/<slug>` on GAME_HOST, which the middleware edge-caches for 7 days (`TTL` in cache.ts). Result: a new hub post or devlog stays invisible until the next game publish, or for up to a week. The hourly cron has the same hole (`src/worker.ts:16-17` purges only `GAME_HOST/`, not `/<slug>` pages that carry DevlogList). Fix: in `purge` (and `releaseScheduled`), when `env.GAME_HOST` is set also call `purgeAndWarm("https://"+GAME_HOST, ["/", ...publishedGameSlugs.map(s=>"/"+s)])`, or `["/games", ...]` on the main origin when it is unset (only needed for devlog saves where `b.sites` includes "games" or `row.sites_json` did).
2. `src/pages/api/admin/[...path].ts:~506-535` (`replaceEverywhere`). There is no branch for `owner_type === "game"` (games call `setUsage("game", …)`). For a game-owned usage the loop skips the swap, but the trailing `for (const p of paths)` still deletes the old media's `media_usage` row and inserts one for the replacement. Result: the game still references the OLD image, which now shows 0 uses, so `deleteMedia` (line 557, 409-if-used guard) will let you delete it and the game page breaks; the new media is falsely "in use". Fix: add a `game` branch (SELECT draft_json FROM games; `swap(parse(draft_json))`; UPDATE draft_json + updated_at) or skip the usage rewrite when no branch handled the owner (`continue` for unknown types).

**LOW**
